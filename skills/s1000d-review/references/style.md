# 文章の観点（観点 C）: 用語集と書き方の決まり

SKILL.md の Phase 4 で読む。根拠にするのは、利用者が渡したファイルだけ。

## 受け付ける用語集の形式

| 形式 | 読み方 |
|---|---|
| 2 列の CSV | 1 列目が語（または原語）、2 列目が採用語（または「使ってよいか」の値）。1 行目が見出しなら読み飛ばす。区切りが違うとき（タブ・セミコロン）は利用者に確かめる |
| Markdown の表 | 見出し行の列名で意味を決める。列名が「語」「採用語」「禁止語」「備考」のように読めなければ、列の意味を利用者に確かめる |
| DeepL の用語集 | `deepl` の MCP が接続されていれば、`list-glossaries` で一覧にし、`get-glossary-dictionary-entries` で語の対を取り出す。用語集の言語対（例: ja → en）が、レビューする DM の言語と合うものだけを使う。書き込みはしない |
| 書き方の決まりの文書（Markdown） | 1 文ごとの規則（1 文 1 事、能動態など）として読む。規則の番号か見出しを引用する |

JSON など、上に無い形式は、列の意味を利用者に聞いてから読む。推測で読み替えない。

## 用語集の読み方

- 用語集の 1 行は「この語を使う」または「この語を使わない」のどちらかとして読む。どちらか判断できない行は、指摘の根拠にしない
- 照合は本文の文字列に対して行う。語形変化は、利用者が許したときだけ吸収する
- 指摘には必ず用語集の該当行を引用する（ファイル名、行、語）
- 用語集に無い語は、指摘しない。「この語は自然でない」は、観点 C ではなく「用語集の根拠なし」の一般的な所見に回す

## 用語集が無いとき

- 報告の「用語集」の欄に「なし」と書く
- 文章の指摘は、一般的な読みやすさの所見に限る。例: 1 文に手順が 2 つ入っている、指示の対象が文中に無い、同じ部品を 2 つの語で呼んでいる
- この所見には「用語集の根拠なし」の印を付ける。サーバーの判定や用語集に基づく指摘と同じ重さで並べない
- 同じ部品を 2 つの語で呼んでいる場合は、DM の中の語の揺れとして根拠が示せる。どの 2 語がどの箇所に出たかを書く

## STE（ASD-STE100）の辞書を同梱しない理由

- ASD-STE100 の辞書と規則の本文は ASD の著作物で、この Skill と各 MCP は、その本文を再配布する許可を持たない
- 辞書が無いまま「STE に適合している」と LLM が言うと、確かめていないことを確かめたように述べることになる
- したがって、辞書のファイルが渡されていないときは、「STE への適合は判定できない」と答える
- 利用者が辞書のファイル（CSV・Markdown・JSON）のパスを渡したときは、そのファイルを用語集として読み、語の照合だけを行う。規則（文の長さ、語形など）の判定は、利用者が規則を文章で渡したときだけ、その文章を引用して行う

## 機密区分との関係

文章の指摘に本文を引用するときは、SKILL.md の Phase 1 の機密区分の確認が済んでいる DM に限る。済んでいない DM、または「引用しない」と決まった DM は、場所と用語集の行だけを書く。
